# Offboard SC Dev (LI.FI Contracts)

Removes a departing SC team member as a Safe signer, adds their replacement, and rotates every shared SC-owned wallet. Orchestrator only: each rotation is owned by its rotate-* skill. Non-SC (HR/IT) offboarding is out of scope.

v1 is execute-only: the Linear ticket tree must already exist (modeled on EXSC-558). Auto-creating it is a fast-follow — say so up front, and don't silently skip a step because a ticket is missing.

## Inputs

- `--person` — the departing SC dev, from the Linear tree.
- `--removed-signer`, `--new-signer` — personal Safe signer seats to remove and add (human / ticket-sourced).
- `--linear` — parent offboarding ticket. Absent → ask; never invent a tree.
- New deployer, dev, and pauser addresses — generated by a human (Phase 1). Old addresses come from keys or on-chain state, never `config/global.json`.

## Guardrails

- Rotate only deployer, dev, pauser, plus the departing person's personal signer seat. If the tree implies touching refund / feeCollector / withdraw (CTO-owned), stop and escalate.
- Key generation is human. Every Safe proposal (signer swap, deployer owner/CANCELLER moves, pauser cuts) is human Ledger-signed via `script/deploy/safe/confirm-safe-tx.ts`; this skill and the ones it calls hand off and wait.
- No direct cuts, no `SEND_PROPOSALS_DIRECTLY_TO_DIAMOND=true`.
- A failing network in one rotation must not silently abort the others — surface it and let the operator decide. Exit codes: `0` success; `1` real error (report, stop, no retry); `2` recoverable misconfig.

## Workflow

Order: keys first (blocking), then the changes to who can sign (signer swap, deployer), then dev and pauser, then secrets and the gate.

### Phase 0 — Preflight

Report, don't fix silently: the `--linear` tree exists and is the plan (state the execute-only note); departing person, replacement signer, and which shared wallets they held (rotate all three regardless — they had access to all shared keys); `.env` present, `PRODUCTION` correct, `SEND_PROPOSALS_DIRECTLY_TO_DIAMOND` not `true`; Foundry, `gh auth status`, lifi-connect (MongoDB), Slack MCP. Tell the user it will pause for key generation and Ledger signing so they don't sign by hand ahead of it.

### Phase 1 — Generate the new wallets (blocking human step)

The human generates new deployer, dev, and pauser keys plus the replacement signer and provides addresses only. The rotate-* skills sweep the bulk from the old wallets; the new deployer needs bootstrap gas before it can broadcast. Wait for the addresses.

### Phase 2 — Swap the multisig signer

`multisig-rollout` has no owner-swap mode. Run `manageSafeOwner "replace" <network> <DEPARTING> <REPLACEMENT>` (`script/playgroundHelpers.sh`) once per production network. No committed entry point runs it across networks — the commented examples in `executeNetworkActions` (`script/multiNetworkExecution.sh`) are the team's playground; ask how the user wants to run it and don't commit the playground edit. Tron's Safe has no helper: report it as a manual follow-up.

The Safe `swapOwner` is not timelock-wrapped: it lands once signed to threshold and executed. Follow `multisig-rollout`'s signing tail (human Ledger signing → `signatureCount >= 2` → `#dev-sc-multisig-proposals`) and wait for the user to confirm signing.

### Phase 3 — Deployer (heaviest role, first)

```text
/rotate-deployer-wallet --new-address <NEW_DEPLOYER>
```

### Phase 4 — Dev

```text
/rotate-dev-wallet --new-address <NEW_DEV>
```

### Phase 5 — Pauser

```text
/rotate-pauser-wallet --new-address <NEW_PAUSER>
```

Let each skill own its hand-offs and wait for it to report complete.

### Phase 6 — Shared secrets

Work the EXSC-567-style checklist (RPC keys, API tokens, CI secrets, shared credential stores). These live mostly outside `contracts`: coordinate with the owners and record what was rotated. Never mark a secret rotated that this session can't reach — log it as a follow-up.

### Phase 7 — Completeness gate

Once per rotated role:

```text
/check-rotation-status --old-address <OLD_ADDR> --new-address <NEW_ADDR> --role <deployer|dev|pauser> --removed-signer <DEPARTING_SIGNER> --production
```

Per role: deployer — Safe owners (departing out / replacement in; old deployer out / new in), `CANCELLER_ROLE`, whitelist role, funding; dev — staging `owner()`, funding; pauser — funding, CI pauser config. Any red row → back to the owning rotate-* skill for that role and network.

## Verification

Complete only when the signer swap is executed on every production Safe, each rotate-* skill reports complete, every role passes Phase 7 on every network, the secrets checklist is worked (unreachable items logged), and the ticket-tree auto-creation gap is recorded as a fast-follow.
