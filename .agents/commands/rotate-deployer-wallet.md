# Rotate Deployer Wallet (LI.FI Contracts)

The Deployer holds `safeOwners[0]` (a signer on every production Safe), the Timelock `CANCELLER_ROLE`, and the CREATE3 deploy key. Every privilege is Safe/Timelock-governed, so the swaps run as Safe proposals, never owner shortcuts. Orchestrator only: each phase delegates to the named skill or helper.

## Inputs

- `--new-address` (required) — the new deployer EOA, generated by a human. Ask once if missing; never generate it here.
- `--check` — run only `check-rotation-status` and stop (still needs `--new-address`, which the check compares against).

The old address comes from `PRIVATE_KEY_PRODUCTION` in `.env` (Phase 1 derives it), never `config/global.json.deployerWallet` — they can diverge, and the wrong address makes a funded wallet look empty or a rotation look incomplete.

## Guardrails

- Deployer only. Never touch refund / feeCollector / withdraw (CTO-owned).
- Key generation is human. The human Ledger-signs the Phase 2 proposals (`script/deploy/safe/confirm-safe-tx.ts`); hand off and wait — never run the signer.
- Every EVM Safe owner change is a Safe proposal; every role/canceller change is timelock-wrapped. The Tron ownership transfer differs in mechanism but its confirm step is still a Safe/Timelock proposal.
- Preview each step (`--check` / `--dryRun`) and get go-ahead before any broadcast or proposal.

## Workflow

Foundry/bun may need `export PATH="$HOME/.foundry/bin:$HOME/.bun/bin:$PATH"`. lifi-connect is required for the Phase 2 MongoDB signature check.

### Phase 0 — Preflight

`--new-address` checksum-valid and not any current SC/CTO wallet in `global.json`. Report old → new. Present Phases 1–7 and say it pauses for key generation and for Ledger signing of the Phase 2 proposals, then resumes with Phases 3–7. Wait for go-ahead.

### Phase 1 — Bootstrap gas (first, before any governance change)

```text
/sweep-wallet-funds --new-address <NEW> --old-key-env PRIVATE_KEY_PRODUCTION --production
```

Leave enough in the old deployer for any Phase 2 tx it must still broadcast — judge per network from the sweep's balance preview.

Per-address settings that do not carry over on rotation:

- HyperEVM: the new deployer cannot deploy on `hyperevm` until big blocks are enabled (register as a HyperCore Core user, then toggle on) — `docs/HyperEVMBigBlocks.md`.
- Sophon: deploys are gated by a per-EOA allow-list; the new deployer is rejected (`contract deployer address … is not in the allow list`) until the Sophon team adds it. Funding doesn't help. Ask in the Sophon partner channel now — it's async and doesn't block other phases. (`abstract` and `zksync` have no such restriction.)

### Phase 2 — Swap the Safe owner + move CANCELLER_ROLE

`multisig-rollout` has no owner-swap mode. Proposals come from `script/playgroundHelpers.sh`, once per production network:

- `manageSafeOwner "replace" <network> <OLD> <NEW>` — Safe `swapOwner` on the Safe itself (not timelock-wrapped).
- `manageTimelockCanceller "replace" <network> <OLD> <NEW>` — timelock-wrapped revoke/grant of `CANCELLER_ROLE`.

No committed entry point runs these across networks; the commented examples in `executeNetworkActions` (`script/multiNetworkExecution.sh`) are the team's playground. Ask the user how to run them and don't commit the playground edit. Then follow `multisig-rollout`'s tail: human Ledger signing, verify `signatureCount >= 2` in MongoDB, post `#dev-sc-multisig-proposals`.

### Phase 3 — Tron: owner + delegation

```bash
bunx tsx script/troncast/index.ts call --env mainnet <LiFiDiamond from deployments/tron.json> "owner() returns (address)"
```

Owner is the `LiFiTimelockController` from `deployments/tron.json` → nothing to move. Owner is the old deployer → run `script/deploy/tron/transfer-ownership-to-timelock.ts` with `PRODUCTION=true` (`--dryRun`, then `--step 1`, then `--step 2`). The Tron Safe owner swap has no helper (`manageSafeOwner` uses the EVM `propose-to-safe.ts`): report it as a manual follow-up, not done.

The Tron `LiFiTimelockController` also grants `CANCELLER_ROLE` to `tronWallets.deployerWallet` (set at deploy by `deploy-and-register-periphery.ts`). `manageTimelockCanceller` also goes through `propose-to-safe.ts`, so report the Tron revoke-old / grant-new as a second manual follow-up. Read it for the old and the new deployer:

```bash
bunx tsx script/troncast/index.ts call --env mainnet <LiFiTimelockController from deployments/tron.json> "hasRole(bytes32,address) returns (bool)" "$(cast keccak CANCELLER_ROLE),<deployer 0x…>"
```

```text
/move-tron-delegation --old-address <old deployer 0x…> --new-address <NEW> --role deployer
```

### Phase 4 — Config PR

```text
/update-wallet-config --role deployer --new-address <NEW> --production
```

### Phase 5 — Decommission the old key

Once Phase 6 shows the old address holds no Safe-owner / canceller / owner privilege anywhere: remove it from `.env` and secret stores and rotate any CI secret carrying it. Human step — give the checklist; don't touch secret stores.

### Phase 6 — Verify

```text
/check-rotation-status --old-address <old deployer 0x…> --new-address <NEW> --role deployer --production
```

Deployer checks: Safe owners (old out, new in) on every production Safe, `CANCELLER_ROLE` moved, CI funding. Tron counts as done only on Phase 3's diamond owner read, the Tron Safe owner swap (`getOwners() returns (address[])` on `tron.safeAddress` from `config/networks.json`: old out, new in), the Tron timelock `CANCELLER_ROLE` read (old revoked, new granted) and Tronscan delegation evidence. The `swapOwner` lands once signed to threshold and executed; the canceller change also waits out the timelock delay — until then "old" is pending, not failure.

### Phase 7 — Report

Swept networks, Phase 2 proposal nonces + Slack thread + remaining signatures, Tron owner + delegation state, config PR URL, decommission status, check result, and everything still pending.
