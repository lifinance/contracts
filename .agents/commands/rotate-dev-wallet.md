# Rotate Dev Wallet (LI.FI Contracts)

Rotates `config/global.json.devWallet` + `tronWallets.devWallet`, the EOA owning each network's staging LiFiDiamond. Orchestrator only: each phase delegates to the named skill, which owns its own preview, confirmation, and secrets hygiene.

## Inputs

- `--new-address` — the new dev EOA, generated by a human. Ask once if missing; never generate it here. Not needed with `--check`.
- `--check` — run only `check-rotation-status` (changes nothing) and stop.

The old address in `global.json` is reference only; funds/ownership steps derive the sender from the `.env` key (config can be mid-rotation-inconsistent).

## Guardrails

- Dev only. Never touch refund / feeCollector / withdraw (CTO-owned) — stop if the request drifts there.
- Key generation and any Ledger signing are human steps; never self-sign.
- Staging diamonds are EOA-owned, so the transfer is a direct owner tx; any governed change goes through `multisig-rollout`.
- Preview each step and get the user's go-ahead before broadcasting.

## Workflow

Foundry/bun may need `export PATH="$HOME/.foundry/bin:$HOME/.bun/bin:$PATH"`.

### Phase 0 — Preflight

Unless `--check`: `--new-address` is checksum-valid and is not any current SC/CTO wallet in `global.json`. Report old → new (EVM; the Tron base58 is derived inside `update-wallet-config` / `move-tron-delegation`). Present Phases 1–6, say it pauses for human key generation and any Tron Ledger signing, and wait for go-ahead.

### Phase 1 — Start staging ownership transfers (old key)

`OwnershipFacet` is two-step: owner calls `transferOwnership(<NEW>)`, new owner calls `confirmOwnershipTransfer()`. Send every `transferOwnership` from the old dev key now, while it still has gas — Phase 2 sweeps it. Preview, confirm, one network at a time.

Tron staging is out of scope: there is no `deployments/tron.staging.json`, so `transfer-ownership-to-timelock.ts` throws with `PRODUCTION` unset. Report it as not applicable.

### Phase 2 — Fund the new wallet

Only after every Phase 1 tx has landed:

```text
/sweep-wallet-funds --new-address <NEW> --old-key-env PRIVATE_KEY   # staging dev key
```

HyperEVM: the new dev EOA cannot deploy on `hyperevm` until big blocks are enabled for it (per-address L1 setting, not carried over; register as a HyperCore Core user, then toggle on) — `docs/HyperEVMBigBlocks.md`.

Then, from the new key, call `confirmOwnershipTransfer()` on every Phase 1 diamond and read `owner()` back.

### Phase 3 — Tron delegation

```text
/move-tron-delegation --old-address <old dev 0x…> --new-address <NEW> --role dev
```

### Phase 4 — Config PR

```text
/update-wallet-config --role dev --new-address <NEW>
```

### Phase 5 — Verify

```text
/check-rotation-status --old-address <old dev 0x…> --new-address <NEW> --role dev
```

Dev checks: staging `owner()` = new (old owns none) on every EVM network, and CI wallet funding. Tron counts as done only on Phase 3's Tronscan evidence. Complete only when every network passes.

### Phase 6 — Report

Per network: swept/skipped, ownership transferred, Tron delegation verified, config PR URL, check result. List failing networks and human follow-ups (Notion registry, decommissioning the old dev key).
